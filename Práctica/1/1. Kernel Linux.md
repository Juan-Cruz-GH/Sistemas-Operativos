## 1. ¿Qué es GCC?

GCC (GNU Compiler Collection) es una colección de compiladores del proyecto GNU que soporta varios lenguajes de programación, (entre ellos C) arquitecturas de hardware y sistemas operativos.

Para C, su uso típico es: `gcc -o nombreEjecutable sourceC.c`

## 2. ¿Qué es make y para que se usa?

Make es una herramienta de automatización de compilación que se usa principalmente para compilar y gestionar proyectos que contienen **múltiples archivos de código fuente**. Facilita el proceso de compilación al determinar automáticamente qué partes del proyecto necesitan recompilarse y ejecutando los comandos necesarios.

Funciona de la siguiente manera:

- Se usa un archivo Makefile o makefile que contiene las reglas que definen cómo construir el proyecto.
- Las reglas especifican dependencias (qué archivos se necesitan) y comandos (qué hacer cada vez que un archivo cambia).
- Make recompila **solo** los archivos que han cambiado, en lugar de compilar todo. Esto ahorra tiempo y optimiza el proceso de desarrollo.
- Make ejecuta los comandos definidos en el Makefile, que pueden incluir compilaciones con gcc o incluso comandos de shell.
- Para correr el makefile simplemente se ejecuta el comando `make`.
- `make` sin argumentos ejecuta el **primer target** del archivo, de arriba hacia abajo. Si queremos que ejecute un target específico, se pasa el nombre del mismo como argumento.
- Es una buena práctica poner el target **all** PRIMERO dentro del Makefile.

## 4. ¿Qué es el kernel de GNU/Linux? ¿Cuáles son sus funciones principales dentro del Sistema Operativo?

El Kernel de GNU/Linux es el corazón del Sistema Operativo. En sentido estricto, ES el SO.

Es una porción de código que se encuentra en la RAM siempre, funciona para todas las arquitecturas de hardware, usa licencia GPLv2, usa System Calls, y es de código abierto.

Sus funciones principales incluyen:

1. Administrar la memoria.
2. Administrar la CPU.
3. Administrar los procesos.
4. Comunicación y concurrencia.
5. Gestionar la E/S.

## 5. Explique brevemente la arquitectura del kernel Linux teniendo en cuenta: tipo de kernel, módulos, portabilidad, etc.

Linux usa un Kernel **monolítico modular**:

- Es monolítico porque todas las funciones del SO se ejecutan en modo Kernel.
- Es modular porque permite cargar y descargar módulos (como drivers, sistemas de archivos), en **tiempo de ejecución**, sin necesidad de reiniciar la computadora.

Los módulos son porciones de código que extienden la funcionalidad del Kernel sin necesidad de recompilarlo.

Sobre portabilidad, el Kernel Linux está escrito principalmente en C y Assembler y soporta la mayoría de arquitecturas de hardware (x86, ARM, RISC-V, etc) y plataformas.

## 6. ¿Cómo se define el versionado de los kernels Linux en la actualidad?

En la actualidad, los kernels Linux siguen el siguiente esquema de versionado:

**X.Y.Z**

X: Revisión mayor. Cambia con menor frecuencia (cada varios años).
Y: Revisión menor. Solo cambia cuando hay nuevos drivers o caracterı́sticas.
Z: Número de parche.

## 7. ¿Cuáles son los motivos por los que un usuario/a GNU/Linux puede querer re-compilar el kernel?

Un usuario de GNU/Linux puede querer re-compilar el Kernel por varios motivos:

- **Soportar nuevos dispositivos** como por ejemplo una placa de video.
- **Agregar mayor funcionalidad** (soporte de un nuevo filesystem).
- **Optimizar funcionamiento** de acuerdo al sistema en que corre.
- **Adaptarlo al sistema donde corre** (quitar soporte de hardware no usado).
- **Corregir bugs**.

## 8. ¿Cuáles son las distintas opciones y menús para realizar la configuración de opciones de compilación de un kernel? Cite diferencias, necesidades (paquetes adicionales de software que se pueden requerir), pro y contras de cada una de ellas.

Las alternativas para realizar la configuración de opcinoes de compilación de un kernel son principalmente tres:

- **make config**:
  - Es la forma más básica de configurar el kernel. Se ejecuta en la terminal y presenta una serie de preguntas secuenciales sobre las opciones de compilación.
  - No depende de una interfaz gráfica. ✅
  - Funciona en cualquier entorno, incluso en sistemas sin X11. ✅
  - Es tedioso, ya que hay que responder a cada opción manualmente. ❌
  - No permite navegar fácilmente por las opciones. ❌
- **make menuconfig**:
  - Es una versión más amigable de make config, usando una interfaz de texto basada en ncurses que permite navegar por menús.
  - Interfaz más organizada con menús y submenús. ✅
  - Se pueden buscar opciones fácilmente con "/". ✅
  - Más rápido que make config. ✅
  - Requiere ncurses, aunque es un paquete ligero. ❌
  - Sigue siendo en modo texto, lo que puede no ser tan intuitivo para algunos usuarios. ❌
- **make xconfig**:
  - Proporciona una interfaz gráfica basada en Qt, útil para configurar el kernel de forma más visual.
  - Interfaz gráfica intuitiva. ✅
  - Fácil navegación y búsqueda de opciones. ✅
  - Útil para usuarios menos familiarizados con la terminal. ✅
  - Necesita entorno gráfico (X11 o Wayland). ❌
  - Requiere más paquetes y dependencias (Qt). ❌

## 9. Indique qué tarea realiza cada uno de los siguientes comandos durante la tarea de configuración/compilación del kernel:

### a. make menuconfig

Inicia la interfaz de configuración menuconfig. Se puede activar o desactivar muchas características del kernel, ajustar configuraciones de hardware, etc.

### b. make clean

Limpia el árbol de código fuente del Kernel, eliminando archivos generados durante el proceso de compilación anterior. Se usa para asegurar que la compilación se realice desde un estado limpio, sin archivos residuales de compilaciones anteriores.

### c. make (investigue la funcionalidad del parámetro -j)

Busca el makefile y ejecuta sus directivas en orden para compilar el kernel. Este proceso puede ser longevo y puede arrojar errores al terminar.

El parámetro -j se usa para especificar el número de trabajos paralelos que pueden ejecutarse durante la compilación. Esto puede acelerar significativamente el tiempo de compilación en sistemas multicore.

### d. make modules (utilizado en antiguos kernels, actualmente no es necesario)

Compila **únicamente** los módulos del Kernel.

En versiones antiguas del Kernel era necesario compilar los módulos por separado. Sin embargo, actualmente este paso se incluye en el proceso de compilación principal y no se necesita ejecutar por separado.

### e. make modules_install

Luego de compilar los módulos, este comando instala los módulos compilados en el directorio `/lib/modules/<versión-kernel>/`. Los módulos instalados acá pueden ser cargados por el SO cuando sea necesario.

### f. make install

Instala el Kernel compilado en el sistema. Copia el kernel y los archivos necesarios al directorio de arranque del sistema (generalmente `/boot`) y actualiza la configuración del cargador de arranque para que pueda arrancar el nuevo Kernel.

Una vez completado, el nuevo Kernel está listo para ser seleccionado y arrancado durante el proceso de booteo.

## 11. ¿A qué hace referencia el archivo initramfs? ¿Cuál es su funcionalidad? ¿Bajo qué condiciones puede no ser necesario?

El archivo **initramfs** es un filesystem temporal que se monta durante el booteo. Proporciona un entorno mínimo y temporal que permite al SO cargar los drivers necesarios, montar el filesystem raíz real y completar el proceso de booteo.

- Contiene ejecutables, drivers y módulos necesarios para lograr iniciar el sistema.
- Luego del proceso de arranque, el disco se desmonta.

## 12. ¿Cuál es la razón por la que una vez compilado el nuevo kernel, es necesario reconfigurar el gestor de arranque que tengamos instalado?

Una vez compilado el nuevo Kernel es necesario reconfigurar el gestor de arranque para que el gestor sepa cuál Kernel debe cargar al iniciar el sistema, si el viejo, el nuevo, u otro.

El gestor de arranque no tiene conocimiento automático cuando se tiene un nuevo Kernel, y por lo tanto, no lo incluirá en la lista de opciones de arranque del sistema. Solo lo hará cuando se lo reconfigure.

## 13. ¿Qué es un módulo del kernel? ¿Cuáles son los comandos principales para el manejo de módulos del kernel?

- Un módulo del Kernel es una porción de código que puede cargarse o descargarse en la memoria del SO bajo demanda.
- Estos módulos permiten extender la funcionalidad del Kernel sin necesidad de recompilar/reiniciar el sistema.
- Se encuentran en `/lib/modules/{versión-del-kernel}`
- Los comandos principales para el manejo de módulos son:

  - **insmod mi_modulo.ko**: Carga un módulo en el Kernel. No resuelve dependencias automáticamente.
  - **modprobe mi_modulo.ko**: Carga un módulo del kernel y sus dependencias automáticamente.
  - **lsmod**: Ver todos los módulos cargados actualmente.
  - **modinfo mi_modulo.ko**: Muestra información detallada sobre un módulo, como su descripción, versión y dependencias.
  - **rmmod mi_modulo.ko**: Elimina un módulo cargado en el kernel.

## 14. ¿Qué es un parche del kernel? ¿Cuáles son las razones principales por las cuáles se deberían aplicar parches en el kernel? ¿A través de qué comando se realiza la aplicación de parches en el kernel?

Un parche del kernel es una actualización o modificación del código fuente del núcleo del SO, generalmente en forma de un archivo de diferencia (.patch o .diff).

Estos parches se aplican para corregir errores, mejorar la seguridad, añadir nuevas características o mejorar el rendimiento del sistema.

La aplicación de parches en el kernel se hace generalmente usando el comando **patch**. Este comando lee un archivo de diferencias y modifica los archivos originales según las instrucciones del parche. Su sintaxis básica es: `patch <opciones> <archivo_original>`.

## 15. Investigue la característica Energy-aware Scheduling incorporada en el kernel 5.0 y explique brevemente con sus palabras:

### a. ¿Qué característica principal tiene un procesador ARM big.LITTLE?

Un procesador ARM big.LITTLE tiene dos tipos de núcleo:

- Núcleos potentes de alto rendimiento.
- Núcleos menos potentes pero con mucho menor consumo.

Esto permite que el sistema balancee la carga de trabajo entre los núcleos de acuerdo con las demandas actuales de rendimiento y energía. Los núcleos big se utilizan para tareas intensivas en recursos y los LITTLE para tareas menos exigentes.

La idea es mejorar la eficiencia energética.

### b. En un procesador ARM big.LITTLE y con esta característica habilitada. Cuando se despierta un proceso ¿a qué procesador lo asigna el scheduler?

Con la característica Energy-aware Scheduling habilitada en un procesador ARM big.LITTLE, cuando se despierta un proceso, el scheduler lo asigna al núcleo que mejor se adapte a las necesidades de rendimiento y consumo de energía **en ese momento**.

Si el proceso requiere un alto rendimiento, podría asignarse a un núcleo big, mientras que si requiere menos recursos, podría asignarse a un núcleo LITTLE para conservar energía.

### c. ¿A qué tipo de dispositivos opinás que beneficia más esta característica? [Ver la documentación](https://docs.kernel.org/scheduler/sched-energy.html).

La característica Energy-aware Scheduling beneficia especialmente a **dispositivos móviles** para equilibrar el rendimiento y la duración de la batería.
